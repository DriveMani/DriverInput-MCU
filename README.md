### **브랜치 전략**
- `main` 브랜치에 push 금지
- 각자 작업 브랜치에서 개발 후 PR 올리기
    - `feature/*`: 새로운 기능 추가
    - `fix/*`: 오류 수정
    - `refactor/*`: 기능 변화 없이 개선
    - `docs/*`: 문서 작업
- PR에 자신이 한 작업 알아보기 쉽게 작성하기

### **커밋 규칙**

| Type | Description |
| --- | --- |
| feat | 새 기능 추가 |
| fix | 버그 수정 |
| refactor | 기능 변화 없이 코드/구조 개선 |
| docs | 문서 수정 (README, 문서 등) |
| chore | 빌드 / 환경 / 설정 정리 |

```
type: 커밋 메시지(한글로 작성)
```
